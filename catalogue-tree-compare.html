两棵目录树，
如何完成增量同步

由 CatalogueSyncer 持有原树和新树，按父节点与名称匹配、保留既有 ID，并协调 model 层在同一个事务中同步目录与文章。

01

先明确“同一个节点”

原树 originTree 来自数据库；新树 currentTree 来自文件扫描，新树中的 ID 已经重新生成。比较时，先确认父节点匹配，再在这个父节点下按名称查找子节点。

父节点已匹配 ＋ Name 相同 ＝ 同一个目录节点
原树 originTree新树 currentTree操作
存在不存在删除 删除该节点、全部后代，以及它们关联的文章。
不存在存在新增 收集整棵新增子树，保留新生成的 ID。
存在存在复用 将旧目录 ID 赋给新节点，再继续比较子节点。

目录和文章分别保留身份

同一目录节点继续使用旧 Catalogue.ID。两边均有文章时，新树的 Article.ID 也要复用旧值，避免未变化的文章被判成“先删再增”。

移动或重命名属于增删

同名节点换了父目录，或同一父目录下改了名称，都不满足匹配条件。按当前规则，删除旧位置的子树，再新增新位置的子树。

父节点身份按树上的匹配关系确定。 两棵树的初始 ID 不同，不能先用原始的父 ID 判断它们是否相同。递归进入一对已匹配的父节点后，才通过各自的 index[Name] 比较子节点。

03

CatalogueSyncer 管理一次同步任务

Catalogue 表示节点；CatalogueSyncer 持有原树和新树，负责比较及协调持久化；model 根据清单执行数据库事务。每次同步创建一个独立的同步任务对象。

BIZ / 一次同步任务CatalogueSyncer
originTree *Catalogue数据库中的原树 · 首次同步可为 nil
currentTree *Catalogue扫描得到的新树 · 在这里复用原 ID
Compare() 生成变更compareNodes() 递归匹配Sync() 协调落盘与报告

Catalogue保存单个节点的数据，维护 Children、index，提供构树和子树遍历操作。

CatalogueSyncer.Sync()调用比较方法，再调用 model 层保存；事务成功后生成变更报告。

四组数据

AddCatalogues、AddArticles 保存待插入的 ORM；DeleteCatalogueIDs、DeleteArticleIDs 保存旧记录的主键。

节点缺失，通过参数表达

递归始终调用同一个 s.compareNodes(origin, current, ...)。同步对象 s 已存在；origin 或 current 可以为 nil，分别表示新增或删除。

这份实现的输入与生命周期约定
  • 新树非空；原树在首次同步时可以为 nil，此时整棵新树都会进入新增清单。
  • 原树存在时，两棵树属于同一本书，且内存对象彼此独立。
  • 同一父节点下名称唯一，index 与 Children 保持一致；原树已经预加载 Article。
  • flattenInto() 按先序遍历输出目录；新节点和新文章的雪花 ID 唯一。
  • 一个同步对象对应一次任务。下次同步重新读取原树并创建新对象，避免重复应用同一份增删结果。

C. Compare()：对齐 ID，生成变更

这个方法处理内存数据：调整新树中的匹配 ID，并产出变更清单。数据库读写由业务入口和 model 层负责。原树为 nil 时，可直接生成首次同步的新增清单。

biz / (*CatalogueSyncer).Compare()
16 行 · Go
// Compare 对齐新树中的 ID，并生成增删清单；原树保持不动。
func (s *CatalogueSyncer) Compare() (*model.CatalogueChanges, error) {
	if s == nil {
		return nil, errors.New("同步任务不能为空")
	}
	if s.currentTree == nil {
		return nil, errors.New("新树不能为空")
	}
	if s.originTree != nil && s.originTree.BookID != s.currentTree.BookID {
		return nil, errors.New("两棵目录树不属于同一本书")
	}

	changes := &model.CatalogueChanges{}
	s.compareNodes(s.originTree, s.currentTree, 0, changes)
	return changes, nil
}

D. compareNodes()：同步对象的递归辅助方法

接收者 s 表示整个同步任务。origin 和 current 是两侧待比较的节点，递归时显式传入，缺失的一侧使用 nil。文章比较使用三个互斥的平级 if：两边都有时复用 ID，仅原树有时删除，仅新树有时新增。两边都没有文章时，三个条件均不成立。

biz / (*CatalogueSyncer).compareNodes()
82 行 · Go
// compareNodes 比较一对节点；origin 和 current 可以为 nil。
func (s *CatalogueSyncer) compareNodes(
	origin *Catalogue,
	current *Catalogue,
	parentID int64,
	changes *model.CatalogueChanges,
) {
	// 原树不存在：新增当前节点及其全部后代。
	if origin == nil {
		if current != nil {
			current.flattenInto(
				parentID,
				&changes.AddCatalogues,
				&changes.AddArticles,
			)
		}
		return
	}

	// 新树不存在：删除原节点及其全部后代和文章。
	if current == nil {
		catalogues, articles := origin.flatten()

		for _, article := range articles {
			changes.DeleteArticleIDs = append(
				changes.DeleteArticleIDs, article.ID,
			)
		}

		// flatten() 是父节点在前，反向遍历得到子节点在前。
		for i := len(catalogues) - 1; i >= 0; i-- {
			changes.DeleteCatalogueIDs = append(
				changes.DeleteCatalogueIDs, catalogues[i].ID,
			)
		}
		return
	}

	// 根节点的父节点均视为空，因此根节点也按名称匹配。
	if origin.Name != current.Name {
		s.compareNodes(origin, nil, parentID, changes)
		s.compareNodes(nil, current, parentID, changes)
		return
	}

	// 同一节点：只在新树上复用原有目录 ID。
	current.ID = origin.ID

	// 两边都有文章：复用原文章 ID。
	if origin.Article != nil && current.Article != nil {
		current.Article.ID = origin.Article.ID
	}

	// 只有原树有文章：删除。
	if origin.Article != nil && current.Article == nil {
		changes.DeleteArticleIDs = append(
			changes.DeleteArticleIDs, origin.Article.ID,
		)
	}

	// 只有新树有文章：新增。
	if origin.Article == nil && current.Article != nil {
		changes.AddArticles = append(changes.AddArticles, &model.Article{
			ID:          current.Article.ID,
			CatalogueID: current.ID,
			Path:        current.Article.Path,
		})
	}

	// 处理原有子节点：匹配或删除。
	for _, originChild := range origin.Children {
		currentChild := current.index[originChild.Name]
		s.compareNodes(originChild, currentChild, current.ID, changes)
	}

	// 处理新增子节点；已匹配的节点在上一循环中处理过。
	for _, currentChild := range current.Children {
		if _, exists := origin.index[currentChild.Name]; !exists {
			s.compareNodes(nil, currentChild, current.ID, changes)
		}
	}
}

同步对象始终存在，缺失节点通过参数表示。 先处理 origin == nil 的新增分支，再处理 current == nil 的删除分支，之后才访问节点字段。两侧节点都为 nil 时直接返回。

递归调用节点状态处理方式
s.compareNodes(nil, current, parentID, changes)只有新节点收集整棵新增子树。
s.compareNodes(origin, nil, parentID, changes)只有旧节点收集整棵旧子树及文章的删除 ID。
s.compareNodes(origin, current, parentID, changes)两边都有节点按名称匹配、复用 ID，再比较子节点。

新增子树的父 ID 必须正确。 父节点匹配后，current.ID 已经被替换成旧 ID。递归时将它传给 flattenInto()，新子树才会连接到数据库中已有的父节点。

E. Sync()：协调事务保存并返回报告

Sync() 先调用 Compare()，再将清单交给 model.ApplyCatalogueChanges()。只有事务提交成功，才返回成功报告。同步对象保留原树快照；由调用方在成功后使用新树。

biz / (*CatalogueSyncer).Sync()
23 行 · Go
// Sync 完成一次比较与落盘，成功后返回变更报告。
func (s *CatalogueSyncer) Sync() (*reporter.Report, error) {
	changes, err := s.Compare()
	if err != nil {
		return nil, err
	}

	if err := model.ApplyCatalogueChanges(changes); err != nil {
		return nil, fmt.Errorf("同步目录树失败: %w", err)
	}

	// 到这里事务已提交。两棵树继续保存在任务对象中，供调用方使用。
	return &reporter.Report{
		CatalogueReport: &reporter.CatalogueReport{
			AddItemQuantity:    len(changes.AddCatalogues),
			DeleteItemQuantity: len(changes.DeleteCatalogueIDs),
		},
		ArticleReport: &reporter.ArticleReport{
			AddItemQuantity:    len(changes.AddArticles),
			DeleteItemQuantity: len(changes.DeleteArticleIDs),
		},
	}, nil
}

F. model：在同一个事务中逐条执行

放在 model 包中，依赖 fmt 和 treeSync/db。事务执行细节集中在这里，按删除文章、删除目录、新增目录、新增文章的顺序执行。

model / ApplyCatalogueChanges()
46 行 · Go
func ApplyCatalogueChanges(changes *CatalogueChanges) error {
	tx := db.DB.Begin()
	if tx.Error != nil {
		return fmt.Errorf("开启事务失败: %w", tx.Error)
	}

	committed := false
	defer func() {
		if !committed {
			_ = tx.Rollback().Error
		}
	}()

	// 先删除文章，再删除目录。
	for _, id := range changes.DeleteArticleIDs {
		if err := tx.Delete(&Article{}, id).Error; err != nil {
			return fmt.Errorf("删除文章 %d 失败: %w", id, err)
		}
	}

	for _, id := range changes.DeleteCatalogueIDs {
		if err := tx.Delete(&Catalogue{}, id).Error; err != nil {
			return fmt.Errorf("删除目录 %d 失败: %w", id, err)
		}
	}

	// 新增目录按父节点在前的顺序写入。
	for _, catalogue := range changes.AddCatalogues {
		if err := tx.Omit("Article").Create(catalogue).Error; err != nil {
			return fmt.Errorf("新增目录 %d 失败: %w", catalogue.ID, err)
		}
	}

	for _, article := range changes.AddArticles {
		if err := tx.Create(article).Error; err != nil {
			return fmt.Errorf("新增文章 %d 失败: %w", article.ID, err)
		}
	}

	if err := tx.Commit().Error; err != nil {
		return fmt.Errorf("提交事务失败: %w", err)
	}

	committed = true
	return nil
}
为什么新增目录使用 Omit("Article")？

目录 ORM 已经声明文章关联，GORM 默认可以自动保存非空关联。这里使用两组切片分别插入目录和文章，因此使用 Omit("Article")，让文章由后面的文章循环保存。

05

事务的执行顺序

删除与新增都要满足关联关系。整棵子树的删除列表来自先序列表的反向遍历；新增列表则继续使用先序顺序。

tx := db.DB.Begin()全部操作共用一个事务
  1. 删除文章先处理 DeleteArticleIDs，解除文章对目录的引用。
  2. 删除目录：子节点 → 父节点按 DeleteCatalogueIDs 的既定顺序，逐条执行删除。
  3. 新增目录：父节点 → 子节点先序输出保证新增父目录先写入；已有父目录使用复用后的旧 ID。
  4. 新增文章文章的 CatalogueID 指向已存在或刚插入的目录节点。
Commit() → Sync() 返回报告 → Book 使用新树中途错误 / panic → defer 尝试 Rollback()

模型中的 Catalogue 和 Article 没有声明 gorm.DeletedAt，上面的 Delete() 是实际删除记录。报告数量按成功提交的变更清单长度统计。

从 Book 入口创建同步任务

在 Book.Build() 已查询并填充书籍信息之后，调用下面的辅助方法。它准备两棵树，创建 CatalogueSyncer 并启动同步，事务成功后再令 Book.Catalogue 指向新树。

// syncCatalogue 放在 biz/book.go 中，由 Book.Build() 调用。
func (b *Book) syncCatalogue(rootPath string) (*reporter.Report, error) {
	orm := &model.Catalogue{}
	rows, err := orm.FindByBookID(b.ID)
	if err != nil {
		return nil, fmt.Errorf("获取书籍目录失败: %w", err)
	}

	var originTree *Catalogue
	if len(rows) > 0 {
		originTree = &Catalogue{}
		if err := originTree.buildFromRows(rows); err != nil {
			return nil, fmt.Errorf("恢复原树失败: %w", err)
		}
	}

	currentTree := &Catalogue{}
	if err := currentTree.buildFromPath(b.ID, b.Title, rootPath); err != nil {
		return nil, fmt.Errorf("构建新树失败: %w", err)
	}

	syncer := NewCatalogueSyncer(originTree, currentTree)
	report, err := syncer.Sync()
	if err != nil {
		return nil, err
	}

	// 只在事务成功提交后，让书籍采用新树。
	b.Catalogue = currentTree
	return report, nil
}

首次同步也走同一个入口

数据库中没有目录时，originTree 保持 nil。Compare() 会收集整棵新树，包括根节点和文章，随后由相同的事务函数保存。

根节点同样按名称匹配

代码把根节点的父节点视为空。根名称不同，会整树删除旧节点、整树新增新节点。若希望书名改变时保留根 ID，需要单独定义根节点按 BookID 匹配的规则。

已有字段的更新是下一类操作

当前范围是新增、删除和 ID 复用。同名同父节点的 Type 或文章 Path 改变时，需要在清单中增加字段更新项，并在同一事务中执行。

原树快照与最终树各有用途

Compare() 只修改新树中的匹配 ID；原树保留旧身份和删除依据。Sync() 成功返回后，业务入口通过 b.Catalogue = currentTree 采用新树。

目录与文章各自比较

匹配目录下，两边都有文章就复用文章 ID；仅旧树有文章就删除；仅新树有文章就新增。文章的 CatalogueID 使用已对齐的目录 ID。

每次任务创建一个同步对象

一次成功同步后，下一次任务重新读取数据库并重新构建新树。同步对象持有的是本次任务的两份输入，避免重复调用 Sync() 应用相同增删。

接入分工： 在 biz/catalogue_syncer.go 中新增 CatalogueSyncer、Compare()、compareNodes() 和 Sync()；Catalogue 保留构树、索引、扁平化和打印；model 层保存 ORM 与事务函数；Book.Build() 调用同步入口。
